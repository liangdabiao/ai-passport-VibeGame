# 约束驱动的玩法设计（设计宪法方法）

> 来源：PokeWalk `docs/01-constitution.md` 的方法论。这是三个案例里"游戏性好"的真正来源：**把硬件约束在策划落笔之前变成设计决策**。

## 1. 为什么需要宪法

> "这类项目最常见的失败方式是：策划做出一个很好的游戏，然后发现电池撑不住、三个键点不动、flash 塞不下。因此硬件约束必须在策划落笔之前定稿。"

宪法是一份 L0 文档：硬件约束 → 每条约束推出的设计决策 → 玩法核心循环。后续一切玩法争论以它为裁判。

## 2. 约束→形态的推导示范（PokeWalk 全文级示范）

**电池预算直接决定玩法形态**：
- 520mAh + Wi-Fi 扫描峰值 200~300mA 脉冲 → **屏幕不能常亮，游戏不能实时**。
- 推导出：「设备揣兜里、后台低频扫描、静默累积；玩家偶尔掏出，30 秒处理一批」——Tamagotchi + 宝可梦步行者形态。
- 四条白捡的好处：不需连续动画、不需实时战斗、一天五次×30 秒更适合品类、三键操作压力骤降。

**约束不止是限制，还是风格与机制来源**：

| 约束 | 实际带来了什么 |
|---|---|
| 屏幕不能常亮 | 后台累积+短会话形态 |
| 显示带宽受限 | "大色块+低帧率"恰是 DMG 时代原生表达（复古像素风不是妥协是认同） |
| 无 IMU | "移动量"指标摇不出来，比步数抗作弊 |
| 无 GPS | Wi-Fi 指纹在室内往往比 GPS 更准，天生离线隐私好 |
| 三按键 | 光标式导航天然适合列表型交互（卡牌/菜单/文字冒险都是天然形态） |
| 无 PSRAM | 横带渲染 → 复古逐行绘制美学 |

## 3. 宪法文档模板（写 `docs/01-constitution.md`）

```markdown
# 设计宪法 v1
## 0. 硬件约束清单（从 bsp_pins.h/实测来，不凭印象）
- 可用堆 231KB；整屏帧缓冲不可能
- 三键 ADC；无触摸
- 520mAh；Wi-Fi 扫描脉冲 200~300mA
- Flash 8MB，资产预算 XXX KB
- RTC 漂移 ±5%（跨关机计时需校时锚点）
## 1. 每条约束 → 设计决策
（每条一行：因为 X，所以我们 Y；Y 是玩法层面的，不是技术层面的）
## 2. 玩法核心循环
（一句话：玩家在 30 秒会话里做什么；后台在两次会话之间积累什么）
## 3. 会话形态
（频率×时长；短会话原则：掏出→看→按几下→收起）
## 4. 页面清单与三键语义表
（每页：名称/功能/上/下/OK/长按）
## 5. 数据规模预算
（存档 X 字节；资产 Y KB；RAM 峰值 Z KB）
## 6. 明确不做的事
（防scope膨胀：无联网对战、无实时性、无...）
```

## 4. 内容生产的两条心法

**让时间生产内容，让空间调制内容**（PokeWalk Wi-Fi 感知的核心设计观）：
- 任何基于"见到新 X"的指标都会衰减到零（第一周发现完，第五周变砖）——**任何会衰减到零的指标都不能作为长期驱动力**。
- 可再生信号：时间排程、状态转换、昼夜上下文、久别重逢、驻留时长。
- 降级阶梯设计：最坏退化成纯 Tamagotchi "也没问题，它照样成立"——**玩法要有保底形态**。

**确定性玩法**（PokeWalk 遭遇系统）：
- `seed = crc32(bssid, hour)` 同一 AP 同一小时永远同一个种子——跨设备一致（两人站一起看到同一批怪，无需服务器）、可预测（能做攻略）、可重算（不用存刷新表）、**能在 PC 侧逐值对账**。
- 属性→内容调制：AP 的 RSSI/隐藏 SSID/企业级/瞬现 → 稀有度（"玩家追着奇怪的路由器跑这件事本身就很对味"）。

## 5. 数值纪律

- **数值不手填，从权威来源取**（原作反汇编/官方数据表）；凭记忆手填必错。
- 名词用官方译名，不从英文回译。
- 均匀采样陷阱：不要从全物种池均匀抽（Lv12 遇到 Lv70 是灾难）——按稀有度分档池。
- 平衡不靠感觉：自动化模拟跑分布断言（2304 局自动对战断言通关率/回合数中位数）。
- 稀有度与经济常量全部进内容表并逐值门禁。

## 6. 会话节奏参考值

- 单次交互动作 ≤600ms 动画；战斗回合 600ms；最长演出（进化）~8.5s 可取消。
- 长流程上限：单场战斗 ≤43s（40 回合上限）+ 可跳过。
- 后台积累速率按"一天 N 次会话"校准（如体能 1 小时回满 = 一天 5~6 次会话节奏）。
- 全局资源门槛：挑战类消耗 5/10/20 点体能分档（小/中/大挑战）。

## 7. 选题速查（什么游戏适合这台设备）

**天然适合**：卡牌 Roguelike（Spire 证明）、文字冒险/互动小说、图鉴收集/养成（Tamagotchi 形态）、回合制 RPG、解谜（推箱子/数独/文字解谜）、答题/学习卡（官方三字经方向）、放置/后台累积型、经典街机低帧率移植（Doom 证明连 FPS 都行）。
**需要重新设计**：任何依赖方向键自由移动+实时反应的（要改造操作模型）；依赖触摸的；需要长时亮屏的。
**反问清单**：30 秒会话成立吗？三键+光标能表达全部操作吗？断电即续吗？资产塞得进预算吗？
