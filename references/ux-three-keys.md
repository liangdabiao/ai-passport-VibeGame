# 三键交互与页面 UX 规范

> 三个按键是这台设备最大的交互约束，也是所有"游戏手感"的来源。两个案例（PokeWalk/Spire）在此高度一致，说明这些是收敛的最佳实践。

## 1. 全局手势语义（先定全局表，页面只做局部例外）

| 键 | 短按（CLICK） | 长按（LONG） |
|---|---|---|
| 上（A/UP） | 光标上一项 | （Spire 战斗页：暂停菜单） |
| 下（B/DOWN） | 光标下一项 | **返回上一页（0.6~0.8s）** |
| 确定（C/OK） | 确认/执行 | （PokeWalk：全局熄屏；Spire 战斗页：结束回合） |

**必须统一的规则**：
- 所有页面（包括只有 1~3 个选项的页面）统一用光标选择 + 确认，不搞"按键即执行"的例外。
- **长按不额外触发短按**：底层在长按完成时抑制随后的 click（BSP 行为或状态机 long_sent 标志），导航 helper 只认 CLICK。
- 双击不移动光标（nav_direction 只在 `ev == CLICK` 时返回非零）。
- **重操作配重手势**：永久删除/无确认无撤销的丢弃 → 长按；轻浏览 → 短按。

## 2. 统一导航 helper（PokeWalk 模式，全游戏共用）

```c
static inline int  nav_direction(btn, ev);   // CLICK: UP=-1, DOWN=+1
static inline bool nav_confirm(btn, ev);     // OK + CLICK
static inline bool nav_return(btn, ev);      // DOWN + LONG
static inline unsigned nav_list_selection(btn, ev, count, current) {
    return count ? (current + count + nav_direction(btn, ev)) % count : 0;   // 环形滚动
}
```

页面 key 处理标准形状：

```c
void play_xxx_key(bsp_btn_t btn, bsp_btn_ev_t ev) {
    if (nav_return(btn, ev)) { nav_back(PAGE_IDLE); return; }
    if (nav_direction(btn, ev)) { s_sel = (s_sel + count + nav_direction(btn, ev)) % count; draw_all(); return; }
    if (!nav_confirm(btn, ev)) return;
    switch (btn) { case BSP_BTN_OK: /* 执行 */ }
}
```

## 3. 全局占用手势（写文档防重踩）

- PokeWalk：**C 长按被 main.c 全局拦截作熄屏**，不转发页面——"任何页面都不能用它"（曾给某页面安排"C 长按丢弃"，实际那个手势到不了页面）。
- 输入过滤层两处入口（壳层+游戏层）统一处理熄屏唤醒；**唤醒按键不同时操作游戏**。

## 4. 提示行治理（"一键一事"）

- 屏幕上常驻一行按键提示（如 `[A]照料 [B]菜单 [C]确认`）。
- **单行、每个 action ≤2 字**（宽度审计 ≤232px）；文案进单一来源表（Python `strings.py` 的 KEYS），不硬写固件。
- 修过的真实缺陷全是"UI 承诺的与实际行为不符"：提示写 `[A]选中` 但按 A 只移光标（阻断级）；死按钮（按键只打串口屏幕零变化）；静默失败（球用完按 A 无反应）→ 屏显"没有球了"。
- **想表达"单击 X/双击 Y"表达不出来时，该改的是交互（一键一事），不是文案格式。**

## 5. 完成后自动导航的判据

> 玩家在这一刻有没有选择可做？没有就自动跳，有就留在原地改提示行。

- 捕获成功自动回列表页 ✅（没有选择）；进化完成自动回主页 ✅；**战斗打完不跳** ❌（"打完去抓"是真实选择）。
- 实现三细节：先清状态与 timer 指针再跳页（否则 exit 重复删 timer）；停留期按键只把计数推到最后一拍不直接跳（**跳转只有一条路径**）；跳页必须在 LVGL 任务里调（lv_timer 回调天然合规）。

## 6. 列表与选中态视觉

- 环形滚动（0 处回绕到末项）。
- 选中态：Spire 用金色 2px 边框 vs 普通 1px + 卡牌上浮 6px/110ms；PokeWalk 用光标 sprite + 聚焦色。
- **手牌/列表 + 虚拟槽**：`item_count = 实体数 + 1`（末尾固定"结束回合"），空手按确认也能结束回合。
- 每页 3~5 项为宜（240×320 竖屏，字 14~16px）；更多项分页/分组。

## 7. 战斗页面布局范式（Spire v1.4 宝可梦式对角）

- 怪物图右上 (140,44,92,80)，怪物血条/意图/状态左上 (8,8,120,78)。
- 角色图左下 (12,104,88,80)，角色血条/能量右下 (116,104,116,80)。
- 手牌横排底部 y≈210（中张放大突出：54×60 / 56×64 / 54×60）。
- 对话框 (12,196,216,74) 演出时覆盖手牌区。
- 状态用短文字徽章："毒3/易2/弱1"（敌我各最多 3 枚）。
- **出牌/敌方行动时**：手牌隐藏 → 对话框逐条演出（520/720ms/条）→ 结束后卡牌回场动画 → 恢复选牌。播放期间锁输入。

## 8. 反馈与动效原则

- 每次有效操作必须有可感知反馈：音效（导航/确认/无效三档）+ 视觉（选中变化/飘字/抖动）。
- 无效操作也要反馈（屏显"没有球了"，不是静默）。
- 动效短促：抖动 55ms×3、上浮 110ms、脉冲 150ms、横幅 800ms——**小屏上长动画=折磨**。
- 飘字用固定对象池；动画前删旧动画防叠加。

## 9. 熄屏与电源 UX

- 60s 无操作自动熄屏；某键长按手动熄屏。
- `nav_screen_busy()` 区分"有限动画/定时结果保持亮屏" vs "输入选择/待机呼吸不阻止超时"。
- 拿不到 LVGL 锁时丢键要记账（`screen_idle_input_dropped()`）。
- 熄屏期间后台活动降频（扫描 30→60s）。
- 唤醒后第一个按键只唤醒不操作游戏。

## 10. 页面架构选择（与路线联动）

| 模式 | 适用 | 核心 |
|---|---|---|
| 页面表 + enter/exit/key（路线 B） | 链式流程游戏（P1→P2→P3 带参数） | `PAGES[]` 显式表 + `nav_go()`，跳转关系集中一处 |
| 页面枚举 + 状态机 handle_input（路线 A） | 分支复杂、页面多 | `state->page` switch + 每页 selected 字段 + 结构化 update 返回 |

两者都拒绝 LVGL group/indev 焦点模型（为触摸设计，与三键不匹配）。

## 11. 交互验收清单（发布前过一遍）

- [ ] 每页提示行如实标注实际可用手势
- [ ] 没有死按钮（按键必有效果或有提示）
- [ ] 长按返回在所有页面一致且不触发短按
- [ ] 列表环形滚动，确认键在空列表安全
- [ ] 演出/动画期间输入被吞且有明确结束恢复点
- [ ] 熄屏/唤醒不误触发游戏操作
- [ ] 战斗等长流程有跳过/加速手段（长按或双击）
- [ ] 60s 无操作会熄屏（除非有意的保持场景）
